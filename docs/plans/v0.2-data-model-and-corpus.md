# v0.2 — Data model & knowledge corpus (ACCEPTED)

> Status: **accepted** 2026-11-12. Architecture context: [v1.0](v1.0-architecture.md).
> Fictional company: **Kosha Financial** (Indian neobank, partner-bank model). All people are synthetic.

## 0. Ground rules for realism

| Rule | Why it matters |
|---|---|
| Money is `BIGINT` **paise**, never float | Float rounding is the #1 fintech bug interviewers probe |
| All timestamps `timestamptz` in UTC; rendered IST | NEFT/RTGS windows and RBI TATs are IST-based |
| Full Aadhaar is **never stored** — only `aadhaar_ref_token` + last 4 | UIDAI Aadhaar Data Vault rules |
| PAN stored as KMS-encrypted token + last 4; full value only for `kyc:pii` scope | DPDP Act 2023 data minimisation |
| IDs are prefixed ULIDs (`cus_01J…`, `txn_01J…`) | Sortable, non-guessable, self-describing in logs |
| Every format passes real validators: PAN `AAAPL1234C` (4th char `P`, 5th = surname initial), IFSC `XXXX0YYYYYY`, UPI RRN 12 digits, NEFT UTR, GSTIN with checksum, Indian mobile `[6-9]\d{9}`, pincode ↔ state | Recruiters who know fintech will spot fake-looking data instantly |
| Generator is deterministic (`--seed`) | Reproducible tests and demos |

### §1a — Status lifecycles (all enforced by a state-machine table + DB CHECK; illegal transitions rejected)

| Entity | Statuses |
|---|---|
| **Transaction** | `initiated` → `authorised` → `processing` → `pending` → `success` · `credit_delayed` (debited at remitter, beneficiary credit pending — the classic UPI "money gone, not received") · `deemed_success` (NPCI deemed-approved after beneficiary-bank timeout) · `on_hold` (risk/compliance hold) · `under_review` · `pending_settlement` · `settled` · `failed` · `timed_out` · `declined` (limits/insufficient funds/risk) · `cancelled` · `expired` (UPI collect request lapsed) · `returned` (NEFT/IMPS returned by beneficiary bank) · `reversal_initiated` → `reversed` · `partially_reversed` · `refunded` · `chargeback_initiated` |
| **Account** | `pending_activation` · `active` · `kyc_pending` · `dormant` · `inoperative` (RBI: no customer-induced txn for 2 years) · `debit_freeze` · `credit_freeze` · `total_freeze` · `lien_marked` · `on_hold` · `pending_closure` · `closed` |
| **KYC profile** | `not_started` · `pending_documents` · `pending_vcip` · `in_review` · `on_hold` · `escalated` · `verified` · `rejected` · `re_kyc_due` · `re_kyc_overdue` · `expired` |
| **Card** | `inactive` · `active` · `temp_blocked` (user-initiated) · `pin_blocked` · `blocked` · `hotlisted` (lost/stolen) · `expired` · `replaced` |
| **Dispute** | `raised` · `acknowledged` · `awaiting_customer_info` · `under_investigation` · `on_hold` · `chargeback_raised` · `pre_arbitration` · `arbitration` · `resolved_customer_favour` · `resolved_merchant_favour` · `auto_reversed` · `withdrawn` · `closed` |

The generator produces realistic distributions (≈96% success, ≈1.5% failed/declined, small tails of `credit_delayed`, `deemed_success`, `on_hold`, `returned`, reversals) — and the long-tail statuses are exactly what disputes and support SOPs reference.
